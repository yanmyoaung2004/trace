# v0.1.2 — Ideas

---

## 1. Multi-Node Phase 1: S3 Cold Storage Backend

**Why:** Single-node TSE is the last remaining SPOF. MinIO/S3 gives HA for the cold tier, letting multiple nodes share Parquet files.

**What:**
- Parquet writer: add `s3://` path support via MinIO SDK
- Cold reader: read from S3 instead of local filesystem
- Manifest: stays local per node (edge sync keeps it consistent)
- Compactor/GC: work on S3 paths transparently

**Effort:** 1 week

---

## 2. Web-Based Read-Only Dashboard

**Why:** Analysts don't want CLI. A web dashboard showing investigations, cases, SIEM alerts, and TSE status makes Trace accessible to the whole SOC team.

**What:**
- Lightweight HTML dashboard (no JS framework, served from Go binary)
- Investigation list + detail view
- Case list with evidence/IOC display
- SIEM alert timeline
- TSE status widgets (watermark, throughput, disk usage)
- Built on existing `/` dashboard route in `internal/server/sync.go`

**Effort:** 1 week

---

## 3. Email/SMTP Ingestion

**Why:** Many security tools can only send email alerts. Email ingestion turns any email-sending tool into a Trace event source — no API integration needed.

**What:**
- SMTP listener (port 25/587/2525)
- Email → event parser (subject, body, attachments)
- Configurable field extraction (regex-based)
- Routes to SIEM pipeline like any other decoder

**Effort:** 2-3 days

---

## 4. Windows Event Collector (WEC)

**Why:** Windows event forwarding is a native Windows capability. WEC lets Trace collect events from all domain machines without installing agents.

**What:**
- WEC HTTP listener (SOAP/WS-Management)
- Event batch decoder
- Routes to SIEM pipeline
- Works alongside existing `trace-agent` for deeper monitoring

**Effort:** 3-5 days

---

## 5. Performance: Hot Store Write Path via Channel

**Why:** The queue package is built but not wired into production. Events go directly to SQLite, bypassing backpressure. Wired queue would give spill-to-disk + drop protection.

**What:**
- Wire `IngestQueue` → `BatchWriter` → `SQLiteHotStore` as the default write path
- Currently: `WriteBatch` → direct SQLite INSERT
- Proposed: `WriteBatch` → `Queue` → `BatchWriter` → SQLite
- Adds backpressure, spill-to-disk, drop counters

**Effort:** 1-2 days

---

## 6. gRPC API (read-only)

**Why:** External tools need a way to query investigations, cases, and search events without going through the CLI.

**What:**
- Define `.proto` service for read operations (ListInvestigations, GetCase, SearchEvents)
- Generate Go gRPC server code
- Add to `trace serve` alongside existing HTTP server
- gRPC reflection enabled for `grpcurl` debugging

**Effort:** 3-5 days

---

## 7. Docker Compose Stack for Production

**Why:** One-command production deployment with MinIO + multi-node TSE + dashboard.

**What:**
- `docker-compose.yml` with:
  - 2x `trace serve --tse` nodes
  - MinIO for shared S3 storage
  - Litestream for SQLite WAL streaming
  - Nginx reverse proxy for dashboard
- Documented in deployment guide

**Effort:** 2-3 days
